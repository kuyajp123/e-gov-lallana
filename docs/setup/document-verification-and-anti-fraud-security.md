# Document Verification & Anti-Fraud Security Guide

## 1. Executive Summary

Barangay Lallana issues critical legal and civic documents, including:
- **Barangay Clearance**
- **Certificate of Indigency**
- **Certificate of Residency**

These documents are regularly presented by residents to banks, employers, courts, embassies, schools, and national government agencies (e.g., SSS, PhilHealth, DFA). 

To ensure complete document authenticity, non-repudiation, and protection against counterfeiting or illicit modification, the e-Gov Lallana platform incorporates an end-to-end **Anti-Fraud QR Verification System**. Every generated document is cryptographically sealed and verifiable in real time via any smartphone camera or the internal staff QR scanner.

---

## 2. Multi-Layer Security Architecture

The verification system is structured in five complementary defensive layers:

```
+-------------------------------------------------------------------------+
| Layer 1: Unique Sequential Reference System (REQ-YYYY-NNNN)             |
|          Enforces strict annual ordering & database-level uniqueness    |
+-------------------------------------------------------------------------+
                                    |
+-------------------------------------------------------------------------+
| Layer 2: High-Entropy Cryptographic Token (32-character CSPRNG)         |
|          192 bits of entropy; impossible to guess or brute-force        |
+-------------------------------------------------------------------------+
                                    |
+-------------------------------------------------------------------------+
| Layer 3: Cryptographic Integrity Signature (HMAC-SHA256)                |
|          Binds token, reference, resident ID, & server private key      |
+-------------------------------------------------------------------------+
                                    |
+-------------------------------------------------------------------------+
| Layer 4: State Machine & Temporal Expiration (6-Month Lifespan)         |
|          Automatic expiration tracking + instant administrative revoke  |
+-------------------------------------------------------------------------+
                                    |
+-------------------------------------------------------------------------+
| Layer 5: Tamper-Proof Audit Logging & Scan Tracking                     |
|          Live scan counts, timestamps, and suspicious activity tracking |
+-------------------------------------------------------------------------+
```

---

### Layer 1: Unique Sequential Reference System
* **Format:** `REQ-{YEAR}-{SEQUENCE}` (e.g., `REQ-2026-0001`, `REQ-2026-0002`).
* **Database Constraint:** The `reference_code` column on the `document_requests` table has a strict `UNIQUE` index. Two records can never share the same reference code.
* **Concurrency Locking:** Generated via [`App\Services\Document\ReferenceCodeGenerator`](file:///c:/Users/Paul/Projects/e-gov-lallana/app/Services/Document/ReferenceCodeGenerator.php) inside a database transaction with pessimistic locking (`lockForUpdate()`), eliminating duplicate numbers during high concurrency.
* **Purpose:** Provides a human-readable filing identifier for receipts, physical folders, and administrative search.

---

### Layer 2: High-Entropy Cryptographic Token
* **Format:** 32-character random alphanumeric string generated by a cryptographically secure pseudo-random number generator (`Str::random(32)`).
* **Entropy:** $\approx 190$ bits of combinatorial entropy ($62^{32}$ combinations).
* **Purpose:** Unlike sequential reference codes which are easily guessed (e.g., guessing `REQ-2026-0003` comes after `REQ-2026-0002`), the token embedded in the QR code cannot be guessed or brute-forced.

---

### Layer 3: Cryptographic Integrity Signature (HMAC-SHA256)
* When a certificate is issued, [`App\Services\QrCode\QrCodeService`](file:///c:/Users/Paul/Projects/e-gov-lallana/app/Services/QrCode/QrCodeService.php) generates an HMAC-SHA256 digital signature:
  $$\text{Signature} = \text{HMAC-SHA256}\Big(\text{Token} \mathbin{\Vert} \text{ReferenceCode} \mathbin{\Vert} \text{ResidentID} \mathbin{\Vert} \text{"barangay-lallana"},\ \text{APP\_KEY}\Big)$$
* **Tamper Proofing:** The secret `APP_KEY` resides strictly on the server and is never exposed to clients.
* **Database Tamper Detection:** If an unauthorized actor directly edits the database (e.g., changes the resident ID or reference code on a compromised database), the calculated hash will not match the stored `security_hash`. The verification system will immediately flag the document as `tampered` / `Suspected forgery`.

---

### Layer 4: State Machine & Temporal Expiration
* **Validity Period:** Official barangay documents are configured with a strict 6-month lifespan (`expires_at = now()->addMonths(6)`). Once expired, the scanner flags the certificate as `expired`.
* **Instant Revocation:** If a document is discovered to have been obtained under false pretenses or is subject to a legal hold, barangay administrators can set its status to `revoked`. Any subsequent scan instantly warns the verifier that the certificate has been cancelled.
* **Statuses:**
  - `active` / `authentic`: Genuine, valid, and within unexpired timeframe.
  - `expired`: Document passed its 6-month validity period.
  - `revoked`: Cancelled or revoked by Barangay Lallana officials.
  - `tampered`: Signature mismatch indicating database or payload alteration.
  - `not_found`: Code does not exist in official records.

---

### Layer 5: Audit Trail & Scan Forensics
* Every scan event automatically increments `scanned_count` and updates `last_scanned_at` in the database.
* Provides forensic evidence for the Barangay in dispute cases (e.g., confirming whether an employer or agency verified the clearance on a specific date).

---

## 3. High-Tolerance Physical QR Code Specifications

* **Error Correction Level:** **Level 'H' (High)** Reed-Solomon error correction.
  - Recovers up to **30% of data loss or physical damage**.
  - Ensures the QR code remains fully scannable even if the printed certificate is folded, creased, stained, or partially torn.
* **Vector Quality:** Embedded in generated PDFs as a high-resolution Scalable Vector Graphic (SVG) data URI (`data:image/svg+xml;base64,...`), preventing pixelation or blurriness during physical printing.

## 4. Verification Methods

### A. Public Verification (Third Parties, Employers, Banks)
1. The third party opens any camera app on iOS or Android.
2. The camera detects the QR code and prompts to open:
   `https://<barangay-domain>/verify/qr/{token}`
3. The server validates the cryptographic token, expiry, and signature.
4. An official verification badge is displayed with:
   - Official Seal of Barangay Lallana & Trece Martires City.
   - Resident Full Name.
   - Document Type (Barangay Clearance, Residency, Indigency).
   - Reference Code (matches printed document).
   - Date of Issuance & Expiration Date.
   - Authenticity Status Badge (`VERIFIED AUTHENTIC`, `EXPIRED`, or `REVOKED`).

### B. Internal Staff QR Scanner (Barangay Hall Desk)
1. Staff navigate to `/admin/qr-scanner`.
2. Uses the workstation webcam, USB barcode/QR scanner, or mobile device camera.
3. Supports live continuous scanning with success audio chimes.
4. Also supports manual fallback entry: staff can enter either the **32-character token** or the **Reference Code (`REQ-YYYY-NNNN`)**.
5. Once scanned, staff can immediately click **"View Full Document Details"** to open the resident's household record, history, and official PDF reprint.

## 5. Client & Auditor FAQ (Threat Model Matrix)

| Threat / Scenario | Attacker Action | System Defense & Outcome |
|---|---|---|
| **Photoshop / Counterfeit Reference** | Attacker creates a fake certificate with a fictional number like `REQ-2026-9999`. | **BLOCKED:** The reference code does not exist in the database. Scanner reports: *"Document verification code not found. The certificate may be invalid or forged."* |
| **Token Guessing / Brute Force** | Attacker tries to generate QR codes with random tokens. | **BLOCKED:** 32-character alphanumeric tokens have $\approx 10^{57}$ combinations. Brute forcing is mathematically impossible. |
| **QR Code Swapping** | Attacker takes a valid QR code from Juan's clearance and pastes it onto Pedro's fake clearance. | **BLOCKED:** When scanned, the system displays Juan's name and details from the official server records, immediately exposing Pedro's document as fraudulent. |
| **Expired Document Reuse** | Resident presents a 1-year-old clearance hoping the date won't be noticed. | **BLOCKED:** Scanner instantly flags the document with an amber badge: *"This document has expired. Official barangay clearances are valid for 6 months."* |
| **Revoked Clearance** | A clearance was issued but later revoked due to pending criminal charges. | **BLOCKED:** Scanner instantly flags a red badge: *"This document has been officially revoked or cancelled by Barangay Lallana."* |
| **Direct Database Tampering** | An insider changes the resident's name or reference code directly in the database without authorization. | **BLOCKED:** The HMAC-SHA256 signature calculated from the modified data fails to match the original signature. Scanner reports: *"Document failed security signature verification. Suspected forgery."* |
